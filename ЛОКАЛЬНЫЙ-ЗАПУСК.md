# Локальный конфигуратор для Windows x64

## Готовый переносимый архив

Распакуйте весь ZIP, затем дважды нажмите `Запустить.cmd`.
Откроется Google Chrome независимо от браузера по умолчанию Windows.
Если Chrome не установлен, откроется Microsoft Edge таким же отдельным окном.
Если нет обоих браузеров, запуск сообщит, что нужно установить один из них.
Используется отдельное окно и профиль `.local-run/edge-profile` или
`.local-run/chrome-profile`, чтобы настройки
сохранялись и параметры отключения фонового замедления не зависели от уже
запущенного Edge. Не включайте этот профиль в архив: в нём пользовательские данные.
При первом открытии включён экспертный режим, отключены сетевые функции через
штатную настройку лимитного подключения и отключена аналитика. Это не сетевой
firewall: настройка не гарантирует блокировку всех запросов браузера.
Пользователь может изменить эти настройки, последующие запуски их сохраняют.
Установка Node.js, npm и Git не нужна.
Готовая сборка находится в `src/dist`, переносимый Node.js — в `.runtime/node`.
Ничего скачивать для запуска не требуется. Интернет нужен только сетевым
функциям самого конфигуратора. USB-драйверы и разрешение браузера на доступ
к полётнику могут потребоваться, как и на официальном сайте.

Сервер слушает только `127.0.0.1:8080`. Повторный запуск открывает ту же копию.
Закрытие вкладки не останавливает сервер; перезагрузка Windows останавливает.
Журналы и PID находятся в `.local-run`. Занятый другим приложением порт 8080
приводит к понятной ошибке, посторонние процессы не завершаются.

В архив включены исходники. После их изменения разработчику нужно заново
выполнить `npm ci` и `npm run build`, затем пересобрать архив. Пользователю
это делать не нужно. Не удаляйте лицензии. `.git`, `node_modules` и
`.local-run` в готовом архиве не нужны; `.runtime` и `src/dist` обязательны.

## Как передать на другой компьютер

1. Скопируйте папку проекта в отдельную папку для передачи.
2. В копии исключите `.git`, `node_modules`, `.local-run` и любые личные дампы,
   прошивки и журналы. Не переносите браузерные профили.
3. Обязательно оставьте `.runtime/node`, `src/dist`, `tools/gyro-monitor`, `scripts/start-local.ps1`,
   `scripts/serve-local.mjs`, `Запустить.cmd`, исходники и лицензии.
4. Упакуйте подготовленную папку. На другом ПК полностью распакуйте архив
   в обычную папку, например `C:\Betaflight`, и откройте `Запустить.cmd`.
5. Подключите полётник по USB. При запросе браузера выберите его COM-порт
   или USB DFU для прошивки. Для загрузки дампа нужен обычный режим, не DFU.

Не запускайте программу прямо внутри ZIP. Права администратора обычно не нужны.
Если Windows блокирует скачанный архив, проверьте его источник и используйте
«Свойства → Разблокировать», если этот пункт доступен. Для неопознанного
COM/DFU-устройства могут понадобиться USB-драйверы.

## Исходники с GitHub — не переносимая сборка

Кнопка **Code → Download ZIP** не включает `.runtime/node` и `src/dist`.
Такой архив нельзя просто запустить без подготовки.

Для разработчика: установите Node.js 24, распакуйте исходники и выполните
в папке проекта:

```powershell
npm.cmd ci
npm.cmd run build
```

После этого `Запустить.cmd` сможет использовать установленный Node.js 24.
Для передачи пользователю без установки Node.js добавьте официальную
Windows x64 ZIP-версию Node.js 24 в `.runtime/node` так, чтобы существовал
файл `.runtime/node/node.exe`, сохранив лицензии из дистрибутива.

Внешняя программа калибровки гироскопа дополнительно требует Python и pyserial.
Инструкция установки находится в README, в разделе «Монитор и калибровка
гироскопа». Не переносите её `.venv` с другого ПК: создайте окружение заново.
После обновления `scripts/serve-local.mjs` уже работающий сервер нужно
перезапустить (например, перезагрузить Windows и снова открыть `Запустить.cmd`).
